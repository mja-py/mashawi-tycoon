# Mashawi Tycoon - working notes

Godot 4.7 project (GDScript), mobile renderer, landscape, Android export preset in `export_presets.cfg`.
Godot binary on this Mac: `/Applications/Godot.app/Contents/MacOS/Godot`.

## Verify changes
- Compile check first: `tools/check.sh` (must print `all scripts parse`). A script error otherwise hangs headless runs; use `--quit-after N` as a safety net.
- Logic tests: `Godot --headless --path . -- --tests` (must print `0 failed`).
- Balance (the truth is the played day): `Godot --headless --path . -- --autodays=150 --sim=day --seed=1` plays the real visible day (`DaySim` through `scripts/sim/day_runner.gd`, same ticks, guests and queue, not drawn) with the greedy player in `scripts/sim/autoplayer.gd` (buys whatever pays back fastest: station levels, stages, items, dish upgrades, moves, promos; saves for a better purchase, credits goal rewards, keeps a cash buffer above the family-loan threshold, picks place and price by the analytic estimate) and prints a growth table (passers, buyers, portions, dine-in, crowd turn-aways, profit, money, stage, levels, bottleneck). About 100 s per 150 days. Expected shape on seeds 1-3 (`tests/baselines/played-day-release2b-seed*.txt`): a quiet cart at Souk Al Seef (6-15 buyers, ~50-60 AED/day in the first ten days), stall day 16-27, truck 40-50, kiosk 63-74, restaurant 84-97, flagship 113-126, no loans, 18/18 goals, 4-6k profit/day at day 150. `--sim=fast` (default) is the statistical `FastSim` on the same service data; `--policy=basic` is the old supplies-only player; `--dbg` prints candidate scores and day stats.
- `Godot --headless --path . --script tests/balance_curve.gd` (about 2 min, exits 1) asserts those milestone windows (stall 15-29, truck 40-60, kiosk 60-78, restaurant 78-98, flagship 105-135), zero loans, goals >= 14, dine-in on fixed stages, and that the best rented place beats the free souk net of rent by >= 25% from the stall up. `Godot --headless --path . --script tests/sim_parity.gd` (about 4 min, 51 setups, 16 played seeds) keeps `FastSim` within 15% and `Economy.throughput_estimate` within 20% of the played day; it is marginal at Souk Al Seef (two low setups fail at `--seeds=20`), so re-run it after any traffic, party or service change and never widen the limits to pass.
- Visual: `tools/shot.sh out.png <delay> --phase=day --location=creek --speed=4` then look at the PNG (also prints draw calls). `--stage=3 --stations=counter:4,grill:7,seating:5 --money=90000` forces a plot stage and station levels for screenshots (`--phase=prep --panel=build|goals` for the new tabs). `--fps` shows fps/draw calls in-game; on the web build append `?dev=--fps` to the URL.
- After adding assets run `Godot --headless --path . --import` once. `tools/unused_assets.sh` lists models nothing references (`--delete` removes them; originals stay in `raw/`).
- Exports: `--export-release Android build/mashawi-tycoon-release.apk` (keystore creds in `.godot/export_credentials.cfg`, never committed); `tools/export_web.sh` + `tools/serve_web.sh [port] [log] [cert.pem key.pem]` (binds 0.0.0.0, prints the LAN URL, logs every request plus the phone's console errors / boot milestones / game state that the shell POSTs to `/log` from LAN addresses or with `?dev=--log`; a real phone needs the https form with a self-signed cert because the engine's AudioWorklet only exists in a secure context, localhost excepted; the phone accepts the certificate warning once and the offline cache stays off there) + `node tools/web_smoke.mjs <url> <dir>` (plus `node tools/web_sw_test.mjs <url>` for the PWA cache, `node tools/web_touch_test.mjs <url> <dir> [mouse]` for panel drag-scrolling and `node tools/web_iphone_test.mjs <url> <dir> [chrome]` for the iPhone install guide + save persistence in WebKit, and `node tools/web_compare.mjs <url> <dir> [webkit]` for tap-driven phone screenshots of any build, old or new, to compare side by side; one-time `cd tools && npx playwright install webkit`, and when that stalls at 14 MB fetch the zip it names (`npx playwright install --dry-run webkit`) from the `playwright-akamai` fallback host with curl, unzip it into `~/Library/Caches/ms-playwright/webkit-<build>/` and `touch INSTALLATION_COMPLETE` there) for the web build; all exit 1 on a failed check. `tools/deploy_web.sh` pushes it to `gh-pages`. On web the 3D view renders at `clamp(1.6/devicePixelRatio, 0.75, 1)` of the canvas (`main._apply_web_quality`; `?dev=--scale3d=1` forces full size) and glow is off (`world.gd`). `?dev=--phase=prep%20--panel=menu` on the web URL skips the title; `window.godotState` holds {phase, hasSave, day, money, panel}.

## Conventions
- All tuning lives in `scripts/core/data.gd` (AED); formulas in `scripts/core/economy.gd` (static, pure).
- Progression: `Data.PLOT_STAGES` (cart, stall, truck = the mobile **rig**; kiosk, restaurant, flagship = fixed **plots** per location, `Game.FIXED_FROM_TIER`) and `Data.STATIONS` with levels (cost = base x growth^level, `Economy.station_cost`; visual tiers at levels 1/4/7/10 via `Data.station_tier`). `Game.rig`/`Game.plots[location]` hold the levels; `Game.station_level/buy_station_level/buy_stage/stage_lock_reason`; building the first fixed stage moves the rig's levels into the plot. Items that need a station carry `requires_station`. `Data.GOALS` is a sequential ladder (`Game.claim_goal`, mentor line via the `goal_claimed` signal) solved against played-day numbers (first goal: 8 buyers in a day; `day_portions` counts plates; a location visit counts when a day opens there, not when prep passes through). `Game.what_if(overrides)` returns the context of a hypothetical setup for previews and the autoplayer.
- The day runs on `scripts/sim/throughput.gd` (counter queue -> kitchen station backlog by `station_kind` -> served -> seat), shared by DaySim (payload = Customer) and FastSim (payload = unique customer ID); `Economy.throughput_estimate(ctx)` is the analytic twin (a closed-loop mean value analysis over the buyer budget) used by the Build tab previews, the Supplies estimate, the report's bottleneck line and the autoplayer. All three read one timing table, `Data.SERVICE`, in sim-seconds (a day is 120): order and handoff beats, cook seconds per portion by station kind, `kitchen_crew` speed by stage, patience, dining, measured walking legs. Keep the three in step when changing capacities (`tests/sim_parity.gd`).
- Group orders: one visible buyer is one queue entry carrying `portions` (`Data.PARTY_SIZES` by plot stage, a location's `groups` weights parties of 3+; up to 48 at the flagship). Ingredients are held per portion in `scripts/sim/stock_ledger.gd` when the order is taken and every portion goes through `Game.sell`; add-ons roll per portion; parties above `SERVICE.dine_max_party` take away, one diner holds one chair. Stats: `served` = visible buyers, `portions` = plates, `crowd` = buyers turned away because the street budget was full. `Data.GUEST_BUDGET` caps rigged people at 12 (buyers by stage and counter tier, ambient walkers on their own budget); bigger stages earn through bigger orders, not more bodies. Demand binds by location: the free souk fills a cart and stall, Creek a stall/truck, Downtown the fixed stages (Mall and Global Village are currently weak). Menu prices are clamped to `Economy.price_range(item, loc)` = 0.5x base .. (1.5 + rent/1000)x base, re-applied on moving location and on loading a save (`Game.clamp_prices`).
- Saves: `user://save.json` (+ a `localStorage` copy on web), `SAVE_VERSION` 4 in `game.gd`; `Game._validate()` sanitises every loaded save, so bump the version and extend `_validate` when rules change. Version <= 2 saves (vehicles + one-off upgrades) go through `_migrate_legacy` (levels or refunds). Screenshot runs (`--screenshot`) never write the save. Version 4 preserves negative cash/lifetime losses, validates malformed nested fields, records once-per-day preparation, and commits weather plus a customer seed at opening. Reloading restores that opening checkpoint, not partial-day earnings.
- Every visible string is a key in `assets/i18n/strings.csv` (en, ar); use `tr(key)` and `Loc.money(v)`. Arabic is RTL: build UI with containers, never hard-coded x offsets.
- UI is built in code (`scripts/ui/hud.gd` + `ui_theme.gd`), no .tscn UI. Keep touch targets >= 48 px. The cafeteria palette uses sand paper, charcoal ink, clay red and palm green in `ui_theme.gd`; `UiTheme.skin` returns cached flat style boxes, with no bitmap raster loop at startup. The faint weave and thin divider replace the former star lattice / glossy gold styling. Button variations: Button (clay red), Primary (green), Danger, Ghost/Icon (outlined), Filter/Toggle/Tab (paper, clay red or green when pressed). Use `_toggle_button()` for on/off switches, never `CheckButton` (its knob overlaps Arabic text). The web build has no system-font fallback: only glyphs in Baloo Bhaijaan 2 render (✓ ✕ ● ○ ★ are missing and draw as boxes on the phone; use √ × ◆ ■ ▶, check with fontTools on `assets/fonts/BalooBhaijaan2.ttf`). Desktop screenshots hide this, WebKit screenshots show it. Motion helpers (`_pulse`, `_pop_in`, `_slide_in`, `_stagger_cards`, `_banner`) are at the end of `hud.gd`; the panel backdrop closes only on a left tap outside the panel because wheel events bubble through panels. The loading overlay is hidden two frames after `godot-ready` with a forced `resize` so the canvas has its final size first (iOS Safari toolbar).
- One name per stand: the painted board (cart roof / stall canopy / truck / kiosk) is hidden when signage reaches tier 3 and the pink neon takes its place (`MashawiStand.set_neon`, `Plot.apply`); never show both. Motion: `Plot._grow` raises freshly bought pieces out of the ground, `World.frame_stage/push_in/set_drift` drive the camera (sizes in `STAGE_CAM`), `Hud.fade_through(action)` is the curtain for street rebuilds (new place, wider plot), and `web/shell.html` owns the loading screen (full-bleed Creek key art, compact title, progress %, Play, canvas fade-in; never animate `#play` with a transform, Playwright then sees it as unstable and the web tests hang). Load budget on GitHub Pages: gzip brings the 39.5 MB wasm + 4.4 MB pck to ~13.5 MB on the first visit, then the service worker serves both from the device; the LAN https server sends everything uncompressed with no cache, so phone loads there are slower than production.
- World is data-driven per location layout in `scripts/world/world.gd`. Kenney building footprints are in `BUILDING_DIMS`.
- Draw calls: `ModelLib.flat_material`/`box_mesh`/`cylinder_mesh`/`plane_mesh` return shared cached resources (never mutate them; use `flat_material_unique` for a material you change later). Static repeated scenery goes through `MeshBatch` (`scripts/world/batch.gd`: `add_box/add_cyl/add_model`, one MultiMesh per mesh+material, flushed into `_level` at the end of `World.set_location`); Gulf houses/mosque/Burj live in `scripts/world/gulf_arch.gd`.
- Mobile art: the first cart has a tiled courtyard, planters and a string-light silhouette; early stages leave a gap in the building row. Static imported scenery uses `World._scenery`; rigid cart/character box details use `ModelLib.batch_primitives`, skipping animated joints and independently hidden upgrades. Keep particle spheres at 8 radial segments / 4 rings. UI model icons become bitmap textures after two rendered frames, then free their 3D viewports.
- iPhone play: Supplies has a quoted **Stock today** purchase (`Game.daily_stock_plan/stock_for_today`), using forecast/menu/recipes/current stock plus a 10% buffer, with rent/wages reserved. Whole orders are atomic; repeat taps buy nothing. Add-ons follow DaySim's probabilities. `Economy.supply_packs` finds the cheapest whole-pack combination. Web rendering starts at 75–100% scale and can step down to 60% after sustained slow frames; `--scale3d` disables adaptation. The shell calls `godotSetPaused` on app hiding and portrait guarding, reflected in `godotState.paused`. Regression: `node tools/web_mobile_play_test.mjs <url> <dir>` tests supplies → day → report, duplicate taps, and pause/resume in WebKit.
- `raw/` holds full Kenney kits and is ignored by Godot (`.gdignore`); copy only what is used into `assets/models/`.
- Interactive sales require the actual rigged buyer. All speeds share DaySim’s 60 Hz fixed clock for arrivals, buyers, kitchen, service workers, dining and cleaning. Skip requests 12×; the whole simulation briefly slows to 2× for readable interactions. Ambient RNG is separate from business decisions. At closing, taken orders, deliveries, meals, and table clearing finish before the report. Virtual passers cannot purchase. The WebKit daily-play test checks visible Skip purchases, duplicate taps, portrait pause, and a single saved close.
- Dining is chosen when an order reaches the counter. A food customer reserves a clean chair and walks to it while the kitchen prepares the order. `DiningStaff` collects the meal, carries it along terrace aisles, and delivers before `DaySim` records the purchase and starts the eating timer. Ingredients on a tray are reserved against other sales. Used tables stay blocked until a worker wipes them and carries away dishes. Kiosks have one worker, restaurants add a second with seating, and the Staffroom adds a third. `node tools/web_restaurant_test.mjs <url> <dir>` records the full restaurant day and checks every purchase against a visible buyer.
- New games start `scripts/ui/play_guide.gd`: a non-blocking, bilingual mentor with 16 saved action objectives (`GuideJourney`). It observes real recipe/price edits, stock purchases, orders, handoffs and a full day, then helps review an upgrade, optional promotion and goals. It never buys or edits game values on the player’s behalf. Its compact portrait is capped to 320px, hidden portraits are freed, menus reserve space below the card, and the card sits inside the daily report. Pause/resume from How to play → Play with me; legacy saves remain opt-in. `tools/web_coach_test.mjs URL OUT [en|ar]` plays the actual flow on iPhone WebKit. `scripts/ui/game_guide.gd` retains the eight reference chapters hosted by the same animated abaya vendor. Reopen from the title or Settings; Settings resumes the last chapter. It uses the modal's pause and stacking rules, opens real prep menus without buying anything, and frees its portrait viewport when closed. `node tools/web_guide_test.mjs <url> <dir>` checks new-game entry, both languages, all menu handoffs, replay, credits, and active-day pause/rotation. The app icon is `icon.png`; ownership belongs in the README/LICENSE and Credits, leaving the loader available for future studio branding.
- Fixed terraces use a 1.05 table pitch and expanded per-stage gaps. Keep `FIRST_TABLE_X`, `ROWS`, the entry, and staff routes consistent; `tests/run_tests.gd` checks full seating and chair clearance in all seven districts at all fixed stages, including Majlis layouts. When changing footprints, also check scenery clearance and camera framing.
- Model inspection: `cd tools && node inspect-glb.mjs <file.glb>` (prints size, origin, tris, animations).

- Food selection: `Hud.selected_dish` is empty for the dish roll (`scripts/ui/card_roll.gd`, a swipeable carousel shared by the prep tabs: the focused card plus readable neighbours, each dish card with its price and an on/off/locked status line; locked dishes bake a grey padlocked icon in `Icons.dish_icon`); tapping a card opens one dish sheet, with price and sale status visible first, recipe and enhancement below. `Icons.dish_icon` plates existing models and caches the resulting bitmap. `--uitest` exposes visible button geometry for real canvas taps; `tools/web_menu_test.mjs` checks Arabic/iPhone 14 and English/iPhone SE, including a GitHub Pages-style subdirectory. The landscape install guide is optional (`#installmini`); portrait keeps its instructions. Loading art is `web/static/loading-art.webp` (291 KB), loaded relative to the page without an external font. `tools/export_web.sh` copies it into the export and adds it to Godot's versioned offline cache; it also resolves directory navigations to cached `index.html`. `web_sw_test.mjs` exercises a real offline reload.

- Art direction: the user rejected the procedural rounded characters and custom clothing over Quaternius base meshes. Those experiments are archived only in ignored `raw/art-studies/rejected-prototypes/`. Use finished authored characters/environments as the starting point; do not revive those generators. The rigged Meshy crew and customers in `assets/models/crew` and `assets/models/customers` are the shared cast. The loading illustration is a visual reference, not a usable 3D mesh.
- The user approved `customers/creek-abaya` as the character reference. Crew and abaya colorways share that mesh/rig and its original face via `ModelLib` clothing palette materials; the male crew uses `creek-kandura` with natural skin and beard. Never reintroduce the rejected `souq-woman` or the old crew sculpts archived in `raw/art-studies/retired-cast`. Men's faces must have natural skin tones and no painted blush, lipstick or eyeliner. Preserve the approved facial features when making outfit variations. Three experimental Meshy retextures in `raw/cast-unified` were rejected because they changed the faces; they are not shipped.
- The guide's `character_portrait.gd` renders independently of street resolution, at 2x sampling capped to 768px on its longest side. It advances the rig at 30 Hz in real time, including when street speed is 4x, and frees its viewport on close. The dim street temporarily uses 50% 3D resolution, then restores the previous setting. `tools/web_portrait_test.mjs` checks actual WebGL buffers, frame budget, cleanup and restoration. `World` warms district cast resources one actor per frame below the paving before visible orders. `node tools/revise_cast.mjs` audits source model size/texture/rig budgets; `--apply` restores compact palette PNG atlases from the original private Meshy sources (1024px Creek heroes, 768px crowd, all under 0.85 MB). Keep their Godot texture import lossless (`compress/mode=0`): lossy JPEG/WebP introduced black and white facial seams. `tools/web_cast_review.mjs URL OUT --poses` reviews both vendors through idle, order, collect, line-full, price, angry and sit poses. `Godot --headless --path . --script tests/speed_consistency.gd` checks 48 matched days at all four speeds and both phone frame caps.

- Logic audit: equipment availability is checked on every offered/sold dish, including add-ons after moving between fixed plots and the rig. `Game.sell` accounts for one item; DaySim/FastSim increment lifetime customers once per completed primary order. Day stats carry `_day` so repeat/stale closing callbacks cannot settle twice. FastSim applies real add-on transactions and dining spend to both cash and reports. The logic suite covers these invariants; the mobile test reloads mid-Skip and checks cash/inventory/weather/customer replay, and the restaurant test checks lifetime guests against real receipts.

- Animation playback (`ModelLib`): `idle` and `sit` are ambient loops. They advance on the wall clock at every playback speed (`step_pose` keeps a second clock divided by `ModelLib.sim_speed`, which `DaySim._tick_time` sets), start at a random phase and a +/-6% rate per actor from `_ambient_rng` (never a business RNG; `ModelLib.ambient_variety = false` for stills), and a one-shot's speed never leaks into the loop queued after it (`animation_changed` resets it). Pass a gesture's speed to `play_once(actor, clip, then, speed)`; do not set `speed_scale` afterwards. Queued customers behind the front occasionally play the `glance` one-shot. Never loop a one-shot clip (`collect`, `interact-right`, `order`): it snaps every cycle.
- Clips: `cd tools && node clip_seams.mjs` audits every cast GLB and exits 1 when a looping clip (`idle`, `sit`, `walk`, `carry`) does not return to its first pose or the standing idle turns the body. `node tools/build_cast_clips.mjs [--check]` rebuilds the loops inside the shipped GLBs (calm 4 s `idle`, complete 4 s `glance`, seamless `sit`, server `idle`/`carry`) without touching meshes or textures; re-run `--import` after it. `--cast-review` takes `--screenshot` natively (`--cast-clip`, `--cast-time`, `--cast-detail=0..3`).
- Waiting in the played day is measured in visible seconds: `Data.SERVICE.patience_s` (scaled by the location's patience), the front customer does not accrue wait while giving their own order, and kitchen wait counts only once the buyer stands at the pickup spot or sits (`Throughput.waiting_for_food`). The wait that counts also leaves out the party's own cooking time. Before this every played sale was scored as a full wait and popularity sank to the floor.
- Continue on a day that has already opened (`Game.day_committed()`) resumes the day from its checkpoint instead of returning to planning, so the committed weather cannot be planned around. Station effect copy is checked against `Data.STATIONS` in both languages (`_test_station_copy`); lights, shade and majlis formulas read their data keys.
- Audio beds: the owner asked for a light soundscape with **no music** (2026-11-12); do not add music tracks unasked. `python3 -I tools/build_audio.py` cuts `assets/sfx/ambience/<location id>.ogg` (a missing district plays `street.ogg`; Al Fahidi and the Creek have no recording of their own yet) and `assets/sfx/loops/grill_sizzle.ogg` from the CC0 sources in `raw/audio-candidates/` (numpy + soundfile; no ffmpeg on this Mac). Ambience is the steadiest 30 s of each recording, mono, closed with an equal-power crossfade, levelled to -30 dB RMS (sizzle -33); run `--import` afterwards. `Sfx.play_music` stays as a no-op without files and Settings hides the Music slider while `Sfx.has_music()` is false. On web `window.godotAudio` = {music, ambience, sizzle} names the beds really playing (`web_smoke`, `web_mobile_play_test` check it). The LAN server has no byte-range support, so a phone `<audio src>` fails there: fetch the file to a blob first.
- Modesty and heritage (owner's request, 2026-11-12): the game respects Islamic and Emirati custom. `World.DISTRICT_CAST` uses only modestly dressed characters (abaya and headscarf, kandura, long trousers); `World.RETIRED_CAST` lists shipped models kept off the street (swimwear, shorts above the knee, uncovered hair) and the logic suite fails if one returns. No music, alcohol, pork, gambling, interest-bearing loans or flirtation in text, art or sound. The station with id `music` (kept for saves) is shown as **Hospitality**: a dates tray, dallah and bakhoor corner (`_st_music`, `cart.gd` `_speaker`, icon `icons/dallah` from `tools/make_icon_dallah.py`); never draw speakers, instruments or a performer there. On fixed plots it stands beside the hut's right wall at `_music_spot`, outside the handoff/exit strip (people occupy z 0.45-1.25 in plot-local space). `tools/shot.sh out.png 3 --cast-review --cast-all` lines up every character full length (sorted ids, then the `souq-abaya` variant, then the server) for dress reviews.
